==========================================
  NOTIFICATION-CONFIG.JS - SMS and Email Settings
==========================================

This configuration file acts as the isolated vault for the API credentials and behavior settings for the reminder engine.

------------------------------------------
IMPORTANT CODE SNIPPETS & EXPLANATIONS:
------------------------------------------

1. SECURE GMAIL SMTP SETUP
```javascript
email: {
    enabled: true,
    service: "gmail",
    user: "yugsuthar208@gmail.com",
    password: "jwyd bejh gllk hrxf"
},
```
Explanation:
These lines provide the Nodemailer package the absolute authority required to login directly to Google's Mail Servers via SMTP. By declaring `service: "gmail"`, the server bypasses manual host and port configuration, automatically understanding how to encrypt the transmission. The password is an "App Password"—a specialized 16-character string assigned by Google that strictly grants mail-sending permissions, completely separate from the actual password used to physically login to the Google Account UI.

2. FAST2SMS REST INTEGRATION
```javascript
sms: {
    enabled: true,
    apiKey: "Urq8dcOBhsJzLF5gjNY31eVDZbCXR2xolHkw6vf9TanputGEQKmAw7sl64OeBqfroZInPxYVvdi8DRQ2"
```

Explanation:
This segment holds the unique Authorization Header required to pass the Fast2SMS gateway firewall. Every single Rest GET query generated by the server includes this exact hash string. If the system is breached or the free tier credits run dry, simply altering this string and saving the file instantly redirects the network logic to a parallel account, making it completely decoupled and robust.

3. TEMPORAL SCHEDULING (CRON)
```javascript
reminder: {
    hoursBeforeAppointment: 2, 
    checkIntervalCron: "*/30 * * * *"
}
```
Explanation:
This object strictly controls the Node-Cron temporal library. The `checkIntervalCron` utilizes UNIX temporal formatting. The `*/30` tells the server to trigger a full system database scan exactly on the 30th and 60th minute of every hour, consistently calculating the `hoursBeforeAppointment: 2` logic to find matching rows. This prevents the server from needing to scan every possible second natively, avoiding performance burnout.
